## 分け方と参照の決まり

- 1つのことは1か所にだけ書く。ほかの仕様書に書いてあることは、写さずにリンクで参照する（同じ内容が二か所にあると、片方だけ直されて食い違うため）。
- 用語は1か所にだけ定義する：[`docs/context.md` があればその用語の節、なければ `overview.md` の用語の節]。ほかの仕様書では、定義を書かずにそこを参照する。
- リンクは相対パスで書き、何が書いてあるかを添える。例：「権限の種類は [auth.md の『役割』](auth.md#役割) を参照」。
- 要件 ID は、すべての仕様書を通して重ならないようにする。例：`FR-AUTH-001`（仕様書ごとの略号を入れる）。
- それぞれの仕様書の冒頭に、関連する仕様書へのリンクを書く（親にあたる仕様書と、あわせて読む必要がある仕様書）。
- 仕様書を足す・分ける・名前を変える・消すときは、同じ変更の中で、この一覧と、その仕様書を参照しているリンクも直す。足した仕様書には、この入口からリンクをたどって行き着けるようにする。
- 仕様書の中身を変えたら、それを参照している仕様書に影響がないかを確かめる（参照元は、ファイル名で検索して探す）。
