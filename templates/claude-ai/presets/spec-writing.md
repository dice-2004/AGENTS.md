# プリセット：仕様書作成プロジェクト

claude.ai で仕様書作成用のプロジェクトを作るときに、2つの欄へそのまま貼る文です。
更新日：2026-11-10（アーティファクト「Claude 指示セット」v4 の2節を2欄に分け直し、個人設定と重なる行を削った）

未決：仕様書をどこに作るか（Claude Docs、リポジトリのファイルなど）。決まったら「プロジェクトの指示」に置き場所を1行足す。

## 何に取り組みますか？

```
ソフトウェアやサービスの仕様書を作るプロジェクトです。仕様書1件につき1スレッドで進め、要件を聞き取って、レビュー済みの仕様書を完成させることを目指します。

完成の条件：
- 要件ごとに、確かめられる形で完了の条件が書かれている。
- 未決事項が解消されているか、残っているのはユーザーが残すと決めたものだけになっている。
- 高性能モデルのレビューで指摘された問題に対応している。
```

## プロジェクトの指示

```
- 構成：目的・背景／用語定義／前提・制約／スコープ（対象外も明記）／要件（ID・優先度 Must/Should/Could、機能・非機能）／完了の条件（要件IDごとに確かめられる形で）／未決事項（質問と影響範囲）／決定事項の履歴（日付付き）。
- 曖昧な要件は仮定で埋めず、未決事項として質問にまとめる（仕様書では、個人設定の「仮定を置いて進める」よりこちらを優先する。仕様の誤りは後工程で高くつくため）。
- 仕様書は進捗ドキュメントを兼ねる。決定のたびに決定事項の履歴を更新する。
- 完成前のレビューでは、抜け漏れ・矛盾に加えて、確かめられない要件も指摘させる（レビューの渡し方は個人設定に従う）。
```
